# 输出模板

同一份证据可用于不同场景。先保留结论、支持它的来源、版本和边界，再压缩正文。没有证据时留「待核实」；不要为了填 STAR 补写不存在的事实。

## 个人复盘（默认）

```text
问题：<选一件会改变下次做法的事>
事实与职责：<已确认的行为；本人/协作边界，未知就注明>
判断变化：<原判断，哪条证据改变了它；或当前待验证假设>
已验证 / 未验证：<来源、版本、环境与结论>
下一次亲手做：<制造一个具体场景 → 观察什么 → 什么结果算通过>
```

## 项目档案

- 背景（S）：项目和问题，注明原创、协作、二开或研究。
- 任务（T）：明确本人负责的模块或待核实范围。
- 行动（A）：现象 → 定位证据 → 根因/假设 → 方案与取舍。
- 结果（R）：验证方法、环境、观测结果与剩余边界；可量化才写数字。

## 简历素材

每条写一个可归属本人的动作和一个有证据的结果。实现和上线不能混写。为用户另留证据卡（不放入公开简历正文）：`结论 | 待核实项 | 来源 | 版本/环境`。如果只能证实实现，别写成已验收或带来业务收益。

## 面试案例

用 60–90 秒说明发生什么、自己做了什么、取舍是什么，以及如何验证。准备两条追问：方案在哪种情况下会失败？下一次用什么证据确认这个判断？不把提纲、模拟验收或团队工作当作真实个人经历。
