## 样例 1：hermes-watch（全栈，原创开源）

**角色**：独立开发 | **规模**：69 commits / 24 后端模块 6,275 行 / 235 项后端测试 + 25 项前端组件测试 + 三平台编译 CI

**S 背景**：自托管服务器巡检工具割裂——监控类只有告警没诊断，诊断类只吃 K8s，AI 类架构重。目标：一个 2GB 盒子装下采集→诊断→修复闭环。

**T 任务**：独立设计并实现完整全栈巡检平台，含采集、告警生命周期、根因诊断、审批制修复、MCP 只读工具面。

**A 行动**：
- 设计规则引擎 + LLM 叙事分工（`analysis.py` 786 行）：规则先出事实，AI 只叙事，失败留痕不阻塞
- 实现 refresh 轮换式并发控制：`probes.py` 541 行 URL/TCP/DNS/Push/ICMP 五类拨测 + Gatus 式双阈值防抖
- 落地审批制执行：`executor.py` + `guard.py` 逐段白名单正则校验，20s 超时，`proposal_runs` 全审计
- 实现 Go 出站 Agent（纯 stdlib，HMAC 签名防重放）+ sh+curl 轻量版双形态
- 建 CI：`ci.yml` 每次 push 跑 ruff + 235 项回归 + oxlint + tsc 严格 + 构建 + gofmt/vet
- 实现 metrics 降采样：`scheduler.py` 小时级均值桶（AVG+行数，幂等 UPSERT，固定 90 天）

**R 结果**：v0.4 路线图全勾选；CI 全绿；一键安装脚本 + Docker compose + systemd；无量化生产数据（个人自托管）

**难点 1：跳板场景下 SSH 握手风暴**
- 现象：接堡垒机后每轮巡检握手 2N，主机一多周期被拖垮
- 定位：链式隧道每跳独立握手，连接复用被切断
- 根因：SSH 链式隧道的握手开销随跳板数线性放大
- 解法：跳板连接池——每轮只需 N+1 次握手（N 个跳板 + 1 次复用）；采集层单连接多探针并发（7 往返 → 2 波）
- 验证：git log `feat: 跳板连接池 + events 时间索引：堡垒机每轮握手 2N → N+1`

**难点 2：告警风暴（抖动翻转）**
- 现象：网络抖动导致主机/服务在线状态反复翻转，通知轰炸
- 根因：单阈值判定无滞后区间，一次失败即下线、一次成功即恢复
- 解法：双阈值防抖——连续 N 次失败才下线 / 连续 N 次成功才恢复（默认 3/2）；crit 持续告警周期重发
- 验证：48 桶心跳条带图 + 翻转事件才进时间线

## 样例 2：identity-service（后端安全，原创开源）

**角色**：独立开发 | **规模**：96 commits / 34 轮迭代 / 39 测试模块 284 测试函数 / CI Postgres + 并发套件

**S 背景**：公司多个业务系统各自做账号，重复且不一致；需要把账号/登录剥离成独立服务。

**T 任务**：独立设计并实现统一身份服务，覆盖 JWT/OIDC/MFA/微信扫码/多租户 RBAC/审计。

**A 行动**：
- 设计认证核心 `security.py` 400 行：RS256 JWT + JWKS kid、refresh 轮换、锁定限流
- 实现 OIDC 桥接 `oauth_bridge`：discovery/authorize/token/userinfo/jwks 端点
- 实现 refresh 重放检测 + 并发轮换行锁（`security.py:206`）
- 实现 TOTP MFA（pyotp RFC 6238，XOR 混淆静态存储）
- 实现 HIBP k-anonymity 泄露密码检测（只发 SHA-1 前 5 位）
- 建 CI：Postgres 16 service container 跑 284 测试函数 + ruff + 前端 vitest + 构建

**R 结果**：生产 runbook 就绪；34 轮迭代每轮全绿；演练清单留痕（含 2026-08-31 踩坑）

**难点 1：Refresh Token 并发轮换竞态**
- 现象：两个并发刷新同一 token，都可能读到"active"各自轮换，双发令牌
- 定位：read → rotate 序列无锁，并发请求都通过"still active"检查
- 根因：经典 refresh-token race
- 解法：无锁只读路径处理 99% 正常刷新；实际轮换进 `transaction.atomic()` + `select_for_update()` 行锁；第二请求阻塞后看到 `revoked_at` 已置位，落入重放路径；重放处理在事务外执行保证吊销能提交
- 验证：`test_concurrency.py` 在 CI Postgres 上跑通

**难点 2：JWT 密钥轮换演练踩坑**
- 现象：只跑 `--new-kid` 不切环境变量，`--retire` 拒绝执行（旧 kid 仍是 active）
- 根因：active kid 由环境变量 `IDENTITY_JWT_KID` 驱动，不写环境变量则旧钥仍是 active
- 解法：轮换三步——签发新钥 → 环境变量切 active 并重启 → 退役旧钥；JWKS 按 kid 暴露所有未退役公钥
- 验证：DRILL_CHECKLISTS.md 2026-08-31 演练记录

## 样例 3：Easel（商业产品，脱敏）

**角色**：核心开发 | **规模**：457 commits / 3,533 后端测试文件 + 841 前端测试文件 / 100+ 篇日期化验证文档

**S 背景**：AI 视频生产线桌面端，集成可灵等模型 API、RPA 浏览器自动化、节点式流水线、账号保险库、多平台发布。

**T 任务**：核心开发（桌面端 + 后端服务 + 自动化编排 + 测试与版本验证体系）。

**A 行动**：
- 设计发布批次服务端持有（`POST /api/publish/batch`）：逐平台独立受理、串行执行、持久化到 batches.json
- 实现重复提交三层防线：服务端批次持有 + 平台锁受理回执 + 显式重试只重发明确失败平台
- 实现无头浏览器健康监督：sentinel 页常驻 + 有界 CDP 探测 + supervisor 心跳
- 实现准入控制 `runtime_limits.py`：Pool + Lease 租约，按任务终态释放而非连接释放
- 建立版本验证纪律：每个版本 CHANGELOG 双语 + 验证项逐条数字 + 未做的显式声明"未进行"

**R 结果**：0.11.1 持续发版；单版本验证：批次套件 10/10、回归 427/427、全量 3,159 通过、前端 71/71

**难点 1：多平台发布的"重复提交"防线**
- 现象：自动化发布最致命的故障不是失败，是"以为失败了其实成功了"导致重复发布
- 根因：客户端关页/网络抖动/重试策略任一环节误判都会重发
- 解法：三层防线——服务端批次持有（客户端关页不丢批次）+ 平台锁受理回执（每平台绑 receipt 记 batchId）+ 显式重试只重发"明确失败或未受理"平台，成功与待核实平台绝不重发；重启恢复只标记 interrupted 不自动重提
- 验证：0.11.0 CHANGELOG "任何平台都不会自动重试"

**难点 2：准入控制按任务终态释放**
- 现象：浏览器是稀缺资源，槽位按浏览器进程退出释放则用户关页面不释放，服务器很快 429
- 根因：连接数 ≠ 任务数，按连接释放会双占槽
- 解法：Pool + Lease 租约模式，acquire 时占槽（超限 429 + Retry-After），释放由 Lease.watch(terminal) 每 250ms 观察任务终态驱动；观察异常不算终态证据；LoginAdmission 只给新 runner 记租约，重连不二次占槽
- 验证：`runtime_limits.py` 源码 + 0.11.1 验证记录

## 用法

AI 挖新项目时，参考这 3 个样例的深度和格式：
- 档案版：S/T/A/R + 难点四要素
- 每条难点要有"现象→定位→根因→解法→验证"五段
- 数字必须核实（数代码/查 git log/读 docs）
- 商业项目脱敏（不写客户/域名/产品名）
