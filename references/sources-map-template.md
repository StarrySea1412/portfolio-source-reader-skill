# SOURCES.md 模板（信息源地图）

> 复制到用户仓库根目录，填好后 agent 自动读取。
> 作用：告诉 agent"每个项目的原始信息在哪、二手档案在哪、核实细节去哪里挖"。

## 怎么用

1. agent 先读本文件，拿到"项目→本地路径/git/公开仓库/档案路径/关键文档"对照表。
2. 按用户主方向选 2-4 个项目。
3. 快速摘要读 portfolio 档案；需要细节 cd 到原始项目目录挖。

## 项目 → 信息源对照表（填这个）

```
### <项目名>（一句话定位）
- 本地路径：`c:\path\to\project`
- Git：<N commits，最后 YYYY-MM-DD>
- 公开仓库：https://github.com/user/repo （或"无（内部）"）
- 档案：`projects/<name>/case-study.md`
- 关键文档：`<path/to/docs>`、`<path/to/core_module.py>`
- 挖什么：并发轮换行锁 / 跳板连接池 / metrics 降采样 / 审批制执行 / CI 配置
- ⚠️ 脱敏：是/否（商业项目标"是"）
```

## 填表说明

- **本地路径**：项目在本机的绝对路径，agent 用 `cd` 进去读源码。
- **Git**：commit 总数 + 最后提交日期，agent 用 `git log` 挖"做了什么"。
- **公开仓库**：GitHub/Gitee 链接，agent 用 gh api 读 README/CI。
- **档案**：portfolio 仓库里的 case-study.md 路径，agent 读这个拿已核实摘要。
- **关键文档**：最该读的 1-3 个文件/目录，agent 优先级读这些。
- **挖什么**：这个项目最值钱的 3-5 个点，agent 知道往哪挖。
- **脱敏**：商业项目标"是"，agent 知道不写客户/域名/产品名。

## 跨项目通用素材（可选填）

- 测试规模：<N 项测试 / M 个测试函数 / K 个测试文件>
- CI：<哪些项目有 CI，跑什么>
- 文档纪律：<哪些项目有日期化文档，多少篇>
- 性能优化：<握手 2N→N+1 / 代码缩减 80% / 行数恒定≤2160>
- 安全深度：<JWT/JWKS/Argon2/MFA/OIDC/refresh 重放/HIBP>

## 不能用的（研究/参考/别人项目）

- `<path>`：<是谁的项目，为什么不能用>
- `<path>`：<开源仓库克隆，非用户作品>
- `<path>`：<工作副本，算 1 个项目>

## 维护规则

- 新项目入库：加一行（本地路径 + git + 公开仓库 + 档案 + 关键文档 + 挖什么）
- 每季度核对：git commit 数、last 日期、公开仓库可达性
- 项目重构/迁移：同步更新路径
- 脱敏项目：在"挖什么"行加 ⚠️ 标注
